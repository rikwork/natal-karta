# Project Plan: Карта Дня (Card of the Day)

## Overview
Реализация функционала "Карта дня" на основе классической колоды Таро (78 карт). 
Основная механика:
- Все 78 картинок и их текстовые описания (разделенные на мужские и женские) зашиваются/хранятся в приложении или отдаются сервером как статика.
- До открытия карты пользователь видит загадочную (анимированную или статичную со свечением) "рубашку".
- По клику происходит "магическая анимация", параллельно на сервер уходит запрос.
- Сервер генерирует случайный ID карты от 1 до 78, запоминает его для данного пользователя на текущий день и возвращает клиенту.
- Клиент плавно открывает карту и показывает предсгенерированное константное описание с учетом пола пользователя.
- При повторном заходе в этот же день карта уже открыта на главном экране.

## Project Type

- [ ] Описания для 78 карт сгенерированы (муж/жен версии).
- [ ] В БД добавлена таблица/логика хранения вытянутой карты дня для пользователя (DailyCard).
- [ ] Эндпоинты API: получить карту дня (с генерацией Random ID, если еще не открывали сегодня).

- [ ] Анимация: таинственная "рубашка" до открытия + магическая анимация при клике и перевороте карты.
- [ ] Повторный вход в приложение в тот же день показывает уже открытую карту без анимации генерации.

## Tech Stack
- Frontend: React Native (Expo). Причины: кроссплатформенная мобильная разработка.
- Backend: Ruby on Rails. Причины: текущий стек проекта, быстрая реализация API.
- DB: PostgreSQL.

## File Structure
**Backend (Rails):**
- `app/models/daily_card.rb` (сохранение истории вытянутых карт юзером)
- `app/models/tarot_card.rb` (словарь карт, либо просто константа в `lib/` или `config/`)
- `app/controllers/api/v1/daily_cards_controller.rb` (эндпоинт для запроса карты)
- `db/migrate/xxx_create_daily_cards.rb`

**Frontend (React Native):**
- `src/components/DailyCardWidget.tsx` (компонент на главном экране)
- `src/screens/DailyCardScreen.tsx` (экран с анимацией и детальным описанием)
- `src/services/DailyCardService.ts` (API запросы)
- `src/assets/tarot/cards/` (отдельная папка для 78 картинок лицевой стороны, чтобы не запутаться)
- `src/assets/tarot/back/` (папка для картинки рубашки)
- `src/constants/tarotDescriptions.ts` (JSON с текстами, если храним на клиенте, либо получаем с бека)

## Task Breakdown

### Task 0: Тестовая генерация (Дизайн)
- **Agent**: `frontend-specialist` (или дизайнер)
- **Skills**: `frontend-design`
- **Action**: Сгенерировать 1 тестовую карту Таро и "рубашку" для согласования визуальной стилистики с пользователем.
- **INPUT**: Пожелания к стилю, референсы.
- **OUTPUT**: 2 изображения (карта и рубашка).
- **VERIFY**: Пользователь утвердил стилистику перед массовой генерацией.

### Task 1: Подготовка данных Таро (Контент)
- **Agent**: `database-architect` (или Python скрипт для генерации)
- **Skills**: `database-design`
- **Action**: Сгенерировать JSON-структуру с 78 картами. Для каждой карты нужно: ID, Name, ImageUrl, DescriptionMale, DescriptionFemale. Поместить эти данные либо в seed.rb бэкенда, либо в локальный JSON фронтенда.
- **INPUT**: Текстовые промпты для ChatGPT.
- **OUTPUT**: Полный JSON/ruby Hash со всеми 78 картами.
- **VERIFY**: Убедиться, что есть 78 записей, и в каждой есть 2 варианта описаний.

### Task 2: Backend - API и БД
- **Agent**: `backend-specialist`
- **Skills**: `api-patterns`, `database-design`
- **Action**: Создать модель `UserDailyCard` (user_id, tarot_card_id, date). 
- **Action**: Создать API endpoint `GET /api/v1/user_daily_card`. Логика: если на сегодня для `current_user` записи нет - сгенерировать рандом (1..78), сохранить, вернуть. Если есть - вернуть существующую. 
- **INPUT**: Текущая структура Users.
- **OUTPUT**: Работающий API Endpoint.
- **VERIFY**: Повторный запрос в тот же день возвращает тот же ID. Запрос на следующий день генерирует новый ID.

### Task 3: Frontend - UI/UX "Рубашки" и Анимация открытия
- **Agent**: `mobile-developer`
- **Skills**: `mobile-design`
- **Action**: Создать экран/виджет карты дня. Имплементировать "рубашку" со свечением. При клике запускать анимацию (магическая пыль/вращение), делать запрос к API (Task 2). После ответа API - плавно разворачивать карту.
- **INPUT**: API endpoint, дизайн-задумка.
- **OUTPUT**: Рабочий React Native компонент с анимациями.
- **VERIFY**: Анимация гладкая, карта переворачивается только после получения ID от сервера.

### Task 4: Frontend - Кеширование и интеграция на главный экран
- **Agent**: `mobile-developer`
- **Skills**: `mobile-design`
- **Action**: На главном экране считывать состояние (вытянута ли сегодня карта). Если да - показывать открытую превью-карту с названием.
- **INPUT**: Интеграция с экраном Home.
- **OUTPUT**: Обновленный HomeScreen.
- **VERIFY**: При открытии приложения юзер видит либо рубашку с призывом "Узнай карту дня", либо свою вытянутую карту, если уже тянул сегодня.
